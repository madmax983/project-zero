**[God Functions in Movement and Arrival]**
**Learning:** `movement_system` in `movement.rs` and `process_arrival` in `arrival.rs` had grown into monolithic "God Functions", managing everything from coyote speed threshold checking, environmental penalty calculations, and executing deep `match` logic for specific arrival tasks (e.g., `ConsumeChemical`, `ScrawlMemeticSigil`). This excessive responsibility makes testing difficult, triggers `too_many_lines` clippy warnings, and masks core flow.
**Action:** Extract specific phases (e.g. `calculate_movement_cost`, `try_apply_movement_speed`) and large match arms (`handle_consume_chemical_arrival`, `handle_scrawl_memetic_sigil_arrival`) into helper functions using early returns. This flattens conditionals and transforms large functions into clear pipelines, allowing the removal of the clippy allow attributes.

**[God Functions in Movement and Arrival]**
**Learning:** `movement_system` in `movement.rs` and `process_arrival` in `arrival.rs` had grown into monolithic "God Functions", managing everything from coyote speed threshold checking, environmental penalty calculations, and executing deep `match` logic for specific arrival tasks (e.g., `ConsumeChemical`, `ScrawlMemeticSigil`). This excessive responsibility makes testing difficult, triggers `too_many_lines` clippy warnings, and masks core flow. In addition, `process_single_movement` accumulated too many arguments.
**Action:** Extracted specific phases and large match arms into helper functions (`handle_farm_arrival`, `handle_admin_arrival`, etc.) using early returns, which flattened conditionals. Grouped optional reference parameters into a helper struct `MovementComponents<'a>` to resolve `too_many_arguments` clippy warnings. This transforms large functions into clear pipelines without altering runtime logic.
