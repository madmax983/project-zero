# Spec 978: The Ghost-Worker Assembly

## 1. Overview
"The Ghost-Worker Assembly" allows players to harness the psychic echoes of deceased highly-skilled Pops. When a master worker dies, they leave behind a localized `SkillEcho` entity in the tile where they worked the most. Players can construct a specialized building, the "Echo Reciter," on that tile. This building harnesses the echo to automatically perform the deceased pop's specific job at 50% efficiency without requiring a living worker. However, the eerie, whispered thoughts emitted by the Reciter act as a localized psychological hazard, slowly draining the Morale of any living Pops working in adjacent tiles.

## 2. Dependencies
- `Pop` death and lifecycle systems.
- Spatial grid systems (`GridPosition`).
- `Building` and `Job` systems.
- `Morale` or `Sanity` systems for localized area-of-effect debuffs.

## 3. RED Phase: Tests First

```rust
// tests/ghost_worker_assembly_tests.rs
use bevy::prelude::*;
use crate::layer1::population::{Pop, DeathEvent};
use crate::layer1::map::GridPosition;
use crate::layer1::jobs::JobType;
use crate::layer1::social::morale::Morale;
use crate::layer1::observation::psychic::{
    SkillEcho, EchoReciter, spawn_skill_echo_system,
    echo_reciter_production_system, echo_reciter_morale_drain_system
};

#[test]
fn test_highly_skilled_pop_death_spawns_skill_echo() {
    let mut app = App::new();
    app.add_event::<DeathEvent>();
    app.add_systems(Update, spawn_skill_echo_system);

    let pop_entity = app.world_mut().spawn(Pop).id();
    let position = GridPosition { x: 5, y: 5 };

    // Trigger death event with high skill (e.g., skill level 80)
    app.world_mut().send_event(DeathEvent {
        entity: pop_entity,
        primary_job: JobType::Weaponsmith,
        skill_level: 80.0,
        last_work_position: position.clone(),
    });

    app.update();

    // Query for SkillEcho at the position
    let mut query = app.world_mut().query::<(&SkillEcho, &GridPosition)>();
    let echoes: Vec<_> = query.iter(app.world()).collect();

    assert_eq!(echoes.len(), 1, "A high-skill death should spawn a SkillEcho.");
    assert_eq!(echoes[0].0.job, JobType::Weaponsmith);
    assert_eq!(echoes[0].1.x, 5);
    assert_eq!(echoes[0].1.y, 5);
}

#[test]
fn test_echo_reciter_performs_automated_work() {
    // Assuming a ProductionEvent or similar is generated by jobs
    use crate::layer1::jobs::ProductionEvent;

    let mut app = App::new();
    app.add_event::<ProductionEvent>();
    app.add_systems(Update, echo_reciter_production_system);

    let position = GridPosition { x: 5, y: 5 };

    // Spawn an EchoReciter overlapping a SkillEcho
    app.world_mut().spawn((
        SkillEcho { job: JobType::Weaponsmith, base_efficiency: 1.0 },
        position.clone()
    ));

    app.world_mut().spawn((
        EchoReciter { active: true },
        position.clone()
    ));

    app.update();

    let events = app.world().resource::<Events<ProductionEvent>>();
    let mut reader = events.get_reader();
    let prod_events: Vec<_> = reader.read(events).collect();

    assert_eq!(prod_events.len(), 1, "EchoReciter should generate a production event.");
    assert_eq!(prod_events[0].job, JobType::Weaponsmith);
    assert_eq!(prod_events[0].efficiency, 0.5, "EchoReciter works at 50% efficiency.");
}

#[test]
fn test_echo_reciter_drains_nearby_morale() {
    let mut app = App::new();
    app.add_systems(Update, echo_reciter_morale_drain_system);

    let reciter_pos = GridPosition { x: 5, y: 5 };
    let adjacent_pos = GridPosition { x: 5, y: 6 };
    let far_pos = GridPosition { x: 10, y: 10 };

    app.world_mut().spawn((EchoReciter { active: true }, reciter_pos));

    let living_worker = app.world_mut().spawn((
        Pop,
        Morale { value: 50.0 },
        adjacent_pos
    )).id();

    let safe_worker = app.world_mut().spawn((
        Pop,
        Morale { value: 50.0 },
        far_pos
    )).id();

    app.update();

    let living_morale = app.world().get::<Morale>(living_worker).unwrap().value;
    let safe_morale = app.world().get::<Morale>(safe_worker).unwrap().value;

    assert!(living_morale < 50.0, "Worker adjacent to Reciter should lose morale.");
    assert_eq!(safe_morale, 50.0, "Worker far from Reciter should not lose morale.");
}
```

## 4. GREEN Phase: Minimal Implementation
- Create `src/layer1/observation/psychic.rs`.
- Define `SkillEcho` component containing the `JobType` and `base_efficiency`.
- Define `EchoReciter` component containing an `active` boolean.
- `spawn_skill_echo_system`: Read `DeathEvent`. If `skill_level` > threshold (e.g., 75.0), spawn a new entity with `SkillEcho` and the `last_work_position` from the event.
- `echo_reciter_production_system`: Query for entities with `EchoReciter`. For each, query `SkillEcho` entities at the same `GridPosition`. If found and active, emit a `ProductionEvent` (or execute the relevant job logic) with the job type and 0.5 efficiency multiplier.
- `echo_reciter_morale_drain_system`: Query all active `EchoReciter` entities. For each, iterate through all `Pop` entities with `Morale` components. Calculate distance via `GridPosition`. If distance <= 1 (adjacent), subtract a small amount from their `Morale`.

## 5. REFACTOR Phase: Quality & Design
- **Spatial Indexing:** Instead of an O(N*M) loop checking distances between all Reciters and all Pops in `echo_reciter_morale_drain_system`, utilize the `TerrainGrid` or a spatial hash map to only query Pops specifically in adjacent tiles.
- **Resource Linking:** In `echo_reciter_production_system`, ensure the Reciter doesn't produce "free" goods out of thin air if the job requires raw materials. It should hook into the standard job pipeline, just substituting the living worker's labor with the echo's automated labor.
- **Visuals/UI:** Skill Echoes need a way to be communicated to the player before a Reciter is built, perhaps as a faintly glowing tile overlay in the UI.

## 7. Technical Guidance
- **DeathEvent Enhancements:** You may need to modify the existing `DeathEvent` or the system that emits it to track and include the Pop's `primary_job` and `last_work_position`.
- **Job Subsystem Compatibility:** The `echo_reciter_production_system` might need to be scheduled appropriately so it acts like a normal worker in the standard job evaluation loop, rather than a completely separate production pipeline, to respect input shortages.
