# 175: Bureaucratic Drag

## Overview

As the colony grows, the sheer weight of administration slows everything down. This feature introduces a new abstract resource: **Admin**.

- **Admin Supply**: Generated by `Office` buildings and `Administrator` jobs (Clerks).
- **Admin Demand**: Consumed by every Building and Pop in the colony.
- **Efficiency**: `Supply / Demand` (clamped to max 1.0).
- **Drag**: When Efficiency < 1.0, a global penalty is applied to **Work Speed** and **Construction Speed**.

This creates a soft cap on expansion. To grow larger, you must dedicate a portion of your workforce to non-productive bureaucracy.

#[derive(Resource, Default, Debug)]
pub struct AdminStats {
    pub supply: f32,
    pub demand: f32,
    pub efficiency: f32, // 0.0 to 1.0

#[derive(Component, Default, Debug)]

    pub demand: f32,

### 2. Implement System (`src/layer1/admin.rs`)

```rust
pub fn calculate_admin_stats(world: &mut World) {
    let mut supply = 0.0;
    let mut demand = 0.0;

    // Sum Providers
    let mut providers = world.query::<&AdminProvider>();
    for provider in providers.iter(world) {
        supply += provider.amount;
    }

    // Sum Consumers
    let mut consumers = world.query::<&AdminConsumer>();
    for consumer in consumers.iter(world) {
        demand += consumer.demand;
    }

    let efficiency = if demand <= f32::EPSILON {
        1.0
    } else {
        (supply / demand).clamp(0.0, 1.0)
    };

    world.insert_resource(AdminStats {
        supply,
        demand,
        efficiency,
    });
}
```

## REFACTOR Phase: Quality & Design

- **Scaling**: Demand should probably scale with building tier/size.
- **UI**: Add Admin efficiency to the top bar UI.
- **Optimization**: `calculate_admin_stats` iterates all entities. For large colonies (1000+), this might be slow. Consider using `Changed<Component>` queries or caching totals.
- **Feedback**: Notify player when efficiency drops below thresholds (e.g., 80%, 50%).
